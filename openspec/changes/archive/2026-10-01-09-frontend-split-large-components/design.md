# Design

## Context

See `proposal.md` for motivation. Current state that shapes the approach:

- `ModelSettingsModal.tsx` reads `modelConfig.provider` (typed `'ollama' | 'groq' | 'claude' | 'openai' | 'openrouter' | 'builtin-ai' | 'custom-openai'`, `ModelSettingsModal.tsx:34`) and the provider `Select` (`ModelSettingsModal.tsx:876-883`) offers exactly those 7 values. The JSX is not one block per provider: `requiresApiKey` (`:237-240`) is true for `claude`/`groq`/`openai`/`openrouter` and gates one shared model combobox (`:886-940`) and one shared `ApiKeyField` block (`:1072-1112`) used by all four; `ollama` (`:1117-1195`, `:1195-1362`), `custom-openai` (`:948-1071`), and `builtin-ai` (`:1362-1408`) each have their own dedicated block. A strict `providers/{OpenAI,Anthropic,Groq,OpenRouter}.tsx` split (one file per provider) would mean 4 near-identical files that only differ in which state setter and fallback-model-list they close over — not a real separation of concerns.
- `VoiceprintBrowser.tsx`'s 4 dialogs (`PersonPickerDialog` 70-201, `ConfirmReplaceDialog` 203-250, `ConfirmClearAllDialog` 251-288, `ConfirmPurgeCachesDialog` 289-335) are self-contained function components already, only defined in the same file as the browser; they take props and have no shared internal state with `VoiceprintBrowser`, so extraction is a pure move.
- `VoiceprintBrowser`'s handlers (`handlePlay` 422, `handleReject` 467, `handleVerifyRow`/`handleVerifySpeaker`/`handleVerifyMeeting` 484-528, `handleReconfirmPick`/`handleReconfirmCreate` 530-551, `handleReplacePick`/`handleReplaceSelect`/`handleReplaceCreate`/`handleReplaceAnonymous` 552-604, `handleClearAllConfirm`/`handlePurgeCachesConfirm` 605-620) all close over the same state block (`data`, `stats`, `audioPath`, `speakersList`, `error`, `player`, etc., `:337-352`) and the `load()` refetch (`:353-367`), so they move as one hook, not several.
- `contexts/TranscriptContext.tsx` already delegates its speaker-relabeling logic to `frontend/src/lib/live-speaker-labels.ts` (`rematchTranscripts`, `rewriteTurnsForBinding`, `rewriteTurnsInWindow`, `upsertLiveBlocks`, `resolveLiveBlocks`, imported at `TranscriptContext.tsx:11`), which already has bun tests (`frontend/tests/lib/live-speaker-labels.test.ts`, with one pre-existing failing case tracked in change 02). The remaining untested pure logic in `TranscriptContext.tsx` itself is the dedupe/sort inside `addTranscript` (`:675-686`) and the timestamp formatter inside `copyTranscript` (`:702-712`); everything else in the file is `useState`/`useEffect`/`useCallback` wiring or DOM/`IndexedDB`/`sessionStorage` access that a pure-function test cannot exercise without a React render.
- `hooks/meeting-details/useSummaryGeneration.ts` has one similar pocket of pure logic: `isLegacySummaryEmpty` (`allEmpty` check, `:300`) and the section-formatting loop building `formattedSummary` (`:317-349`), both operating only on plain data (no IPC, no state) already separated from the surrounding polling/IPC code by their own local variables.
- `frontend/package.json` `devDependencies` has `typescript`, `eslint`, `eslint-config-next`, and no test runner at all (checked directly) — `bun` and a `test` script are added by change 02, not by this one. `@testing-library/react` and `happy-dom`/`jsdom` are **not** devDependencies either, and adding either (plus wiring bun's DOM shim) is a separate decision with its own maintenance cost that this change does not need in order to get first coverage on the two files in scope.
- `frontend/.eslintrc.json` is `{"extends": ["next/core-web-vitals", "next/typescript"]}`, and running `cd frontend && npx next lint` today already reports every `any` occurrence (including all 32 in `hooks/`) as `@typescript-eslint/no-explicit-any` at `Error` severity — confirmed by direct output, not assumed. `next lint`'s process exit code is already `1` today for this reason (and for `no-unused-vars`/`react/no-unescaped-entities`). No workflow in `.github/workflows/` invokes `next lint`, so this failing exit code has no effect on CI today.
- `hooks/meeting-details/useModelConfiguration.ts:27,51` and `hooks/meeting-details/useSummaryGeneration.ts:487` cast `invokeTauri(...)` results `as any` — these three sites are exactly the calls that change 08's `lib/ipc/settings.ts` (`getModelConfig`, `getCustomOpenAIConfig`) and `lib/ipc/models.ts` (`getOllamaModels`) replace with typed returns, so fixing them here is a direct consumer of 08's output, not new typing work invented in this change.

## Goals / Non-Goals

**Goals:**

- Make `ModelSettingsModal.tsx` and `VoiceprintBrowser.tsx` composition-only: state/IPC in a hook, dialogs and provider-specific JSX in their own files, so each piece is small enough to read and change in isolation.
- Remove every `any` in `hooks/` (32 sites, 8 files) by typing against real payload types (from `lib/ipc/*` where the value comes from IPC, from existing domain types like `Transcript`/`Summary`/`CurrentMeeting` elsewhere).
- Get first bun-runnable tests for the pure logic inside `TranscriptContext.tsx` and `useSummaryGeneration.ts`, without adding a DOM-testing dependency.
- Zero behavior change: every provider save/load path, every voiceprint dialog action, and every transcript/summary formatting result is byte-for-byte the same after the split.

**Non-Goals:**

- Touching `VirtualizedTranscriptView.tsx` (owned by the in-flight `drop-turn-grouping` change).
- Fixing `any` outside `hooks/` (components/app — left as a follow-up list, see Migration Plan).
- Adding `next lint` to CI, or changing `@typescript-eslint/no-explicit-any`'s severity (it is already `"error"`; see Context).
- Rendering `ModelSettingsModal`/`VoiceprintBrowser` in a test with `@testing-library/react` — deferred (see Decisions D4).
- Rewriting `TranscriptContext.tsx`'s or `useSummaryGeneration.ts`'s control flow beyond lifting the two named pure helpers out of each.

## Decisions

### D1: `hooks/useModelSettings.ts` owns state and IPC; `components/ModelSettings/*` owns JSX only

`useModelSettings.ts` exports one hook returning every piece of state currently declared at `ModelSettingsModal.tsx:126-176` plus the derived flags (`requiresApiKey`, `ollamaEndpointChanged`, `isCustomOpenAIInvalid`, `isSaveDisabled`, `:237-256`) and the handlers (`handleSave` `:617`, `testCustomOpenAIConnection` `:667`, `handleInputClick` `:694`, the provider-model loaders around `:464-604`). It calls `lib/ipc/settings.ts` (`getModelConfig`, `saveModelConfig`, `getApiKey`, `getCustomOpenAIConfig`, `saveCustomOpenAIConfig`, `getAutoGenerateSetting` — the last one documented as calling a currently-unregistered command per change 08 design.md) and `lib/ipc/models.ts` (`getOllamaModels`, `getAnthropicModels`, `getGroqModels`, `getOpenAIModels`, `getOpenRouterModels`, `pullOllamaModel`, builtin-ai listing).

- `components/ModelSettings/index.tsx` becomes the same top-level `return (...)` currently at `ModelSettingsModal.tsx:804` onward, calling `useModelSettings()` for everything it used to hold locally, and rendering the provider `Select` plus one of `HostedProviderFields` / `Ollama` / `CustomOpenAI` / `BuiltIn` based on `modelConfig.provider`.
- `components/ModelSettings/ApiKeyField.tsx` is the block at `:1072-1112` (label, masked input, lock/unlock, show/hide), taking `value`, `locked`, `visible`, and the three toggle callbacks as props — used only by `HostedProviderFields.tsx`, since `custom-openai` has its own inline API key field (`:979`) with different semantics (optional, no lock) that stays in `CustomOpenAI.tsx`.
- `components/ModelSettings/providers/HostedProviderFields.tsx` covers `claude`/`groq`/`openai`/`openrouter`: the model combobox (`:886-940`) plus `ApiKeyField`, parameterized by the provider's model list (`openaiModels`/`claudeModels`/`groqModels`/`openRouterModels` from the hook) and loading flag. This is the one deviation from the brief's literal `{Ollama,OpenAI,Anthropic,Groq,OpenRouter,BuiltIn}.tsx` file list, made because the source JSX already shares this block across the four providers (see Context) — splitting it into 4 files would create duplication the current code does not have.
- `components/ModelSettings/providers/Ollama.tsx` (`:1117-1362`), `CustomOpenAI.tsx` (`:948-1071`), `BuiltIn.tsx` (`:1362-1408`) map directly to their existing JSX blocks.
- Alternative considered: keep one `ProviderSection.tsx` that switches on `modelConfig.provider` internally instead of `index.tsx` doing the switch. Rejected — `index.tsx` already needs the switch to decide which provider-specific loader to fire on mount, so a second switch one level down adds indirection without hiding any complexity.

### D2: `hooks/useVoiceprintActions.ts` owns state, `load()`, and every handler; dialogs move as-is

The hook takes no arguments (mirrors today's zero-argument `useEffect(() => { load(); }, [load])` at `:369-371`) and returns `{ data, stats, error, speakersList, player, playingRowId, failedRowId, hideVerified, ...handlers }`. `VoiceprintBrowser.tsx` (now just the render function) calls the hook once and passes its returned values into the 4 dialogs (moved to `components/Voiceprints/dialogs/PersonPickerDialog.tsx`, `ConfirmReplaceDialog.tsx`, `ConfirmClearAllDialog.tsx`, `ConfirmPurgeCachesDialog.tsx`, each unchanged apart from adding explicit prop types where they closed over module scope before) and the row/table JSX (`:649-957`).

- The hook calls `lib/ipc/speakers.ts` for `list_voiceprints`, `speaker_storage_stats`, `list_speakers`, `get_voiceprint_audio`, `get_meeting_audio_path`, `reject_voiceprint`, `verify_voiceprint`/`verify_speaker`, `reconfirm_voiceprint`, `rematch_meeting_speakers`, `preview_replace_speaker`/`replace_speaker`, `clear_all_voiceprints`, `purge_unconfirmed_caches` (the last few are the ones the handlers at `:530-620` call; exact command names confirmed by reading each handler body).
- Alternative considered: split into `useVoiceprintData` (load/state) and `useVoiceprintActions` (handlers) as two hooks. Rejected for this change — every handler both reads and mutates the same state (e.g. `handleReject` calls `load()` after mutating), so two hooks would need to pass state back and forth between them for no isolation benefit; one hook matches the brief's own naming and the actual coupling in the code.

### D3: `any` removal in `hooks/` is typed from the nearest real source, not `unknown`

Each of the 32 sites gets the type the value actually has:

- `useAutoScroll.ts:6,185` (`segments: any[]`) → typed against the caller's segment shape (a subset of `Transcript`/`LiveTranscriptBlock` fields actually read: `id`).
- `useImportAudio.ts:176,195,236,256` (`catch (err: any)`) → `catch (err)` with `err instanceof Error ? err.message : String(err)` at each site (the pattern already used elsewhere in the same file), since `catch` variables have no annotation to remove in TS ≥4.4 strict mode other than dropping the redundant `: any`.
- `useRecordingStateSync.ts:50`, `useRecordingStop.ts:545,551` (`(window as any).__TAURI__` / `.handleRecordingStop`) → a local `interface WindowWithTauriHooks extends Window { __TAURI__?: unknown; handleRecordingStop?: (callApi?: boolean) => void }` and one `(window as WindowWithTauriHooks)` cast per file, replacing the untyped escape hatch with a named, narrow one.
- `useTranscriptRecovery.ts:170-175` (`(t as any).chunk_start_time` etc.) → the source `t` is retyped to the actual recovered-transcript shape (a `Partial<Transcript>`-compatible interface) once, at the top of the mapping function, removing the need for 5 individual casts.
- `useCopyOperations.ts:9,124,140`, `useMeetingData.ts:9,76,84`, `useMeetingOperations.ts:6`, `useSummaryGeneration.ts:54` (`meeting: any`) → all four hooks' `meeting` prop becomes `CurrentMeeting` (already defined and exported from `components/Sidebar/SidebarProvider.tsx`, and already imported by `useSummaryGeneration.ts` — it is simply typed `any` today instead of using the import that is already one line away).
- `useModelConfiguration.ts:27,51`, `useSummaryGeneration.ts:487` (`invokeTauri(...) as any`) → replaced by calling the typed `lib/ipc/settings.ts#getModelConfig`/`getCustomOpenAIConfig` and `lib/ipc/models.ts#getOllamaModels` from change 08, dropping the cast entirely.
- `useSummaryGeneration.ts:160,177,205,277,300,328,333` → typed against `Summary`/`SummaryDataResponse` (`types/index.ts`) for the IPC-shaped values, and against the new `formatLegacySummaryData`'s own parameter/return types (D5) for the section-loop casts, which disappear once that loop is a typed function instead of inline `any`-cast code.
- Alternative considered: blanket `as unknown as T` at each site instead of fixing the source type. Rejected — `unknown` casts satisfy the compiler without removing the actual type hole; the brief's goal (and `no-explicit-any`'s intent) is a real type at each boundary, which every site above has available already.

### D4: Pure-function extraction, not `@testing-library/react` + `happy-dom`, for first tests

`lib/transcript-formatting.ts` exports `dedupeAndInsertTranscript(prev: Transcript[], next: Transcript): Transcript[]` (the logic at `TranscriptContext.tsx:675-686`) and `formatTranscriptForClipboard(transcripts: Transcript[]): string` (the logic at `:702-712`); `TranscriptContext.tsx`'s `addTranscript`/`copyTranscript` call these instead of inlining the logic. `lib/summary-formatting.ts` exports `isLegacySummaryEmpty(sections: [string, unknown][]): boolean` and `formatLegacySummaryData(sectionOrder: string[], summaryData: Record<string, unknown>): Summary`, replacing the inline logic at `useSummaryGeneration.ts:300,317-349`.

- Why not `@testing-library/react` + `happy-dom`/`jsdom`: neither is a devDependency today, and change 02 (the change this one depends on for a working `bun test` pipeline) adds only `bun`'s own types and a `test` script — not a DOM shim or React renderer. Introducing one now would mean deciding a rendering-test strategy for the whole frontend as a side effect of getting two files their first tests, which is a bigger decision than this change's scope.
- Why pure extraction is sufficient here: both files' *only* currently-untested logic that doesn't require React state, a DOM container, `IndexedDB`, or `sessionStorage` is exactly the four functions above; everything else in these two files is wiring that a pure-function test cannot exercise anyway (rendering it would require `@testing-library/react`, deferred above).
- Recording this as the pattern going forward: any other hook/context that wants coverage before `@testing-library/react` is adopted should look for the same kind of seam (a pure transform called from inside a `useState`/`useCallback` body) rather than trying to test the hook as a whole.
- Alternative considered: test `TranscriptContext.tsx`/`useSummaryGeneration.ts` end-to-end via `renderHook` once `@testing-library/react` is added. Left as an Open Question below — a reasonable next step once that dependency decision is made deliberately, not as a byproduct of this change.

### D5: `formatLegacySummaryData`'s casts are removed by typing its inputs, not by keeping `any` inside a renamed function

The extracted function's signature uses `Record<string, unknown>` for `summaryData` and narrows with `typeof section === 'object' && 'title' in section && 'blocks' in section` (the same guard already at `useSummaryGeneration.ts:327`) before touching `.blocks`, so no `any` moves into `lib/summary-formatting.ts` — this keeps the "remove `any` from `hooks/`" and "extract pure helpers" goals aligned instead of relocating the type hole.

## Risks / Trade-offs

- **`useModelSettings.ts` becomes a large hook file even after the split** (it collects ~40 state values and ~10 handlers) → Accepted: the alternative is splitting state across multiple hooks that all need each other's values (e.g. `requiresApiKey` depends on `modelConfig.provider`, which every provider block also needs), which trades one large file for several tightly-coupled small ones. The win here is moving state/IPC out of the JSX file, not minimizing hook file size.
- **`HostedProviderFields.tsx` combining 4 providers could hide a future provider-specific difference** (e.g. if OpenRouter needs an extra field later) → Mitigation: the component takes an explicit `provider: 'claude' | 'groq' | 'openai' | 'openrouter'` prop, so a provider-specific branch can be added inside it without another full split, and the Decisions section documents why it is one file today.
- **Manual smoke-testing the settings modal and voiceprint dialogs is required** (no `@testing-library/react` coverage yet) → Mitigation: tasks.md includes an explicit manual checklist per provider and per dialog; `npx tsc --noEmit -p .` catches prop/type mismatches from the split, which is the highest-risk regression class for a pure extraction.
- **`hooks/useModelConfiguration.ts:27,51` and `useSummaryGeneration.ts:487` depend on change 08's `lib/ipc/settings.ts`/`models.ts` existing** → Already required by the apply order (08 before 09); if 08 is not yet applied, these three sites fall back to typing the existing `invokeTauri(...)` call's result directly instead of importing from `lib/ipc/*`, with a task-level note to re-point them once 08 lands.
- **`autoGenerateEnabled` still defaults to `true` on fetch failure** (`ModelSettingsModal.tsx:322`, unchanged by this split, and depends on the still-broken `api_get_auto_generate_setting` documented in change 08) → Not a new risk introduced here; called out so it is not mistaken for a regression once `useModelSettings.ts` is the place that code lives.

## Migration Plan

- Order: (1) `useModelSettings.ts` + `components/ModelSettings/*` (largest file, most `any`-adjacent IPC casts to fix per D3), (2) `useVoiceprintActions.ts` + `components/Voiceprints/dialogs/*`, (3) remaining `hooks/` `any` sites not already touched by (1)/(2), (4) `lib/transcript-formatting.ts` + `lib/summary-formatting.ts` extractions and their tests. Each step keeps `ModelSettingsModal.tsx`/`VoiceprintBrowser.tsx` building and behaviorally identical before the next step starts.
- Rollback: each step is an independent file move + type fix; reverting a later step (e.g. the pure-function extraction) does not require reverting the split.
- Follow-up (not in this change): remaining `any` in `components/`/`app/` (59 of the 91 `no-explicit-any` errors `next lint` reports today, after this change's 32 in `hooks/` are fixed), and wiring `next lint` into CI once the codebase is close enough to clean that it is not immediately red.

## Open Questions

- Should `@testing-library/react` + a DOM shim be adopted repo-wide as a follow-up change, to get `renderHook`/component-level coverage for `useModelSettings`, `useVoiceprintActions`, and the two contexts beyond their pure helpers?
- Should the `components/`/`app/` `any` sites get their own change now that `hooks/` is clean, or wait until more of those files route through change 08's `lib/ipc/*` (many are IPC-return casts, the same pattern fixed here)?
