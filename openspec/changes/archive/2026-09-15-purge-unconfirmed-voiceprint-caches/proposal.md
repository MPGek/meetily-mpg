## Why

Unassigned cache rows in `speaker_embeddings` accumulate from every diarization run, and in the Voiceprint browser today they can only be removed one row at a time (`reject_voiceprint`) or together with every confirmed prototype (`clear_all_voiceprints`). Caches are the enrollment substrate: `enroll_cluster` reparents the best-K cache rows of a cluster into a speaker, filtered only by `(meeting_id, cluster_label)` and ordered by duration — with no filter on `model`, `channel`, or provenance. Legacy caches (pre-per-person-split clusters, `resnet34_int8` 256-d rows that never match, caches written before channel/provenance tracking) therefore become prototypes on the next naming or assignment and degrade recognition, while occupying slots under the 64-prototype cap. Users need a way to discard the unconfirmed cache layer without destroying the confirmed speaker prototypes they have already curated.

## What Changes

- Add a bulk repository operation and Tauri command that deletes every unassigned cache row (`speaker_id IS NULL AND meeting_id IS NOT NULL`) and reports how many rows, embedding bytes, stored voice clips, and clip bytes were removed.
- Add a "Remove unconfirmed caches" control to the Storage card of the Settings voiceprint browser, next to the existing "Remove all" action. It is disabled when the cache count is zero, requires an explicit confirmation that states the number of caches and the stored-clip totals, reloads the browser and storage stats afterwards, and invalidates the in-memory `PrototypeStore` for live sessions.
- Confirmed prototypes, registry speakers, `meeting_speakers` cluster bindings and their centroids, expected-speaker allowlists, and per-transcript speaker overrides are left untouched.
- The purge is lossy by design: cache exemplars are only regenerated by running diarization again for a meeting. Existing bindings still support instant re-match because `meeting_speakers.centroid` is stored separately.

## Capabilities

### New Capabilities

None. The behavior extends two existing voiceprint capabilities rather than introducing a near-duplicate.

### Modified Capabilities

- `voiceprint-rejection`: adds a bulk purge of all unconfirmed caches as a distinct operation from the existing per-row cache rejection, with the guarantee that prototypes and registry data are never touched.
- `voiceprint-review`: adds the bulk purge control to the browser's storage summary, including its disabled state, confirmation content, and post-action refresh.

## Impact

- `frontend/src-tauri/src/database/repositories/speaker.rs`: new `purge_unconfirmed_caches` operation and a result type alongside `clear_all_voiceprints`.
- `frontend/src-tauri/src/database/speaker_commands.rs` and `frontend/src-tauri/src/lib.rs`: new command registered in the invoke handler.
- `frontend/src/components/VoiceprintBrowser.tsx`: new control in the Storage card with confirmation and reload.
- `frontend/src/services/recordingService.ts`: typed wrapper for the command.
- No schema migration: the existing `CHECK` constraint already guarantees that `speaker_id IS NULL` implies `meeting_id IS NOT NULL`, so the delete predicate is unambiguous.
- No change to diarization, `load_prototypes`, or recognition thresholds. Recognition already ignores unassigned caches, so this change affects only the enrollment substrate and storage, not how clustering or matching run.
