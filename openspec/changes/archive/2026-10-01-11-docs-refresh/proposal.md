# Proposal

## Why

`docs/CODEBASE_MAP*.md` (17 files, header-stamped `last_mapped: 2026-08-25T10:40:44Z`, git-touched 2026-08-31) was machine-generated by a "Cartographer" tool and has not been regenerated since, while `AGENTS.md`'s own "Recent additions" paragraph (also dated "since last map update, 2026-08-25") has grown into a single 250+-word run-on sentence that nobody will keep extending by hand. Both are already visibly wrong, not just old: `docs/CODEBASE_MAP_MODULE_AI_PROVIDERS.md` documents a `trait LlmProvider { send_request(), list_models(), name() }` and per-provider `OllamaClient`/`OpenAIClient`/... structs that do not exist in the codebase (the real code is free async functions dispatched through one `match` in `summary/llm_client.rs::generate_summary`); `docs/CODEBASE_MAP_MODULE_ANALYTICS.md` documents an `AnalyticsTracker struct` where the real type is `AnalyticsClient` (`frontend/src-tauri/src/analytics/analytics.rs:80`); and `docs/PROJECT_OVERVIEW_FULL.md:103` links to `AUDIO_MODULARIZATION_PLAN.md`, which has never existed in this repository's git history. The repo already runs `graphify` (see `AGENTS.md`'s graphify section) for exactly this kind of codebase navigation, but `graphify-out/wiki/index.md` — the artifact `AGENTS.md` itself says to prefer "if it exists" — has never been generated.

## What Changes

- Fix or remove every dead file/doc reference found in `docs/*.md` and `AGENTS.md` (see Impact for the count).
- **Recommendation B**: shrink the hand-maintained codebase maps to a thin, stable architecture overview, and delegate file-level and symbol-level navigation to `graphify`'s wiki instead of re-authoring 17 files by hand every few weeks:
  - Keep and trim: `docs/CODEBASE_MAP.md` (index — drops the per-module-file table of contents, keeps the system overview and core-capabilities bullets), `docs/CODEBASE_MAP_ARCHITECTURE.md` (system diagram + layer descriptions, with file-count/token-count/"recent work" prose removed), `docs/CODEBASE_MAP_CONVENTIONS.md` (naming/pattern conventions — genuinely slow-changing), `docs/CODEBASE_MAP_OPERATIONS.md` (build/run commands — extended with the frontend test command from change 02 and the clippy CI gate from change 03).
  - Remove (superseded by the graphify wiki, regenerated with `graphify update . --wiki`): `docs/CODEBASE_MAP_MODULES.md`, `docs/CODEBASE_MAP_MODULE_AI_PROVIDERS.md`, `docs/CODEBASE_MAP_MODULE_ANALYTICS.md`, `docs/CODEBASE_MAP_MODULE_AUDIO.md`, `docs/CODEBASE_MAP_MODULE_DATABASE.md`, `docs/CODEBASE_MAP_MODULE_FRONTEND_APP.md`, `docs/CODEBASE_MAP_MODULE_FRONTEND_COMPONENTS.md`, `docs/CODEBASE_MAP_MODULE_FRONTEND_HOOKS.md`, `docs/CODEBASE_MAP_MODULE_NOTIFICATIONS.md`, `docs/CODEBASE_MAP_MODULE_PARAKEET.md`, `docs/CODEBASE_MAP_MODULE_SUMMARY.md`, `docs/CODEBASE_MAP_MODULE_WHISPER.md`, `docs/CODEBASE_MAP_DATA_FLOW.md`, `docs/CODEBASE_MAP_NAVIGATION.md` — these 13 files are exactly the file-level/symbol-level listings that went stale in three weeks and contain the fabricated-trait and wrong-struct-name errors above.
- Rewrite `AGENTS.md`'s "Codebase Map" section (lines 5-21) to point only at the four kept files plus the graphify wiki, and replace the "Recent additions" prose paragraph (line 23) with a pointer to `openspec/changes/archive/` (most-recently-archived first) as the authoritative changelog, instead of a hand-maintained sentence that must be manually extended after every change.
- Add `scripts/check-doc-links.sh` (a small mechanical checker: extract backticked `*.rs`/`*.ts`/`*.tsx`/`*.js`/`*.jsx` references from `docs/*.md` and `AGENTS.md`, resolve each against the repo root / `frontend/src-tauri/src` / `frontend/src` / `scripts`, fail-list any that resolve nowhere) and wire it into `.github/workflows/pr-main-check.yml` as a new, non-blocking step (`continue-on-error: true`), so future drift is visible in CI without gating merges.
- No code, spec, or IPC behavior changes — `skip_specs: true`.

## Impact

- Docs removed: 13 files under `docs/` (listed above).
- Docs trimmed: `docs/CODEBASE_MAP.md`, `docs/CODEBASE_MAP_ARCHITECTURE.md`, `docs/CODEBASE_MAP_CONVENTIONS.md`, `docs/CODEBASE_MAP_OPERATIONS.md`, `AGENTS.md`.
- Docs left alone (out of the CODEBASE_MAP/AGENTS scope, but their dead references are still fixed per the full link check): `docs/PROJECT_OVERVIEW_FULL.md` (dead link to `AUDIO_MODULARIZATION_PLAN.md`, `docs/PROJECT_OVERVIEW_FULL.md:103`), `docs/BUILDING.md`, `docs/GPU_ACCELERATION.md`, `docs/architecture.md`, `docs/building_in_linux.md`.
- New file: `scripts/check-doc-links.sh`.
- CI: one new, non-blocking step added to `.github/workflows/pr-main-check.yml`.
- Dead-reference audit (backticked `*.rs`/`*.tsx?`/`*.jsx?` filenames in `docs/*.md` + `AGENTS.md`, resolved recursively anywhere under `frontend/src-tauri/src`, `frontend/src`, `frontend`, `scripts`, or repo root, excluding `node_modules`/`target`/`.git`/`graphify-out`/`.next`/`.kilo`): of 411 backticked code-file references across 21 markdown files, only 3 fail to resolve to any file in the repo by basename (`PascalCase.tsx`/`snake_case.rs` in `docs/CODEBASE_MAP_CONVENTIONS.md`, which are illustrative naming examples rather than real references, and `core.rs` in `docs/PROJECT_OVERVIEW_FULL.md`, a genuine stale reference — the file was split into per-concern modules and no plain `core.rs` remains, only `audio/core-old.rs`, which is itself dead code slated for deletion in change 01). This basename-anywhere check is deliberately lenient (it does not verify a reference's claimed directory or the symbols/structs/traits it describes) — the more serious rot is semantic, not path-level: see Why (fabricated `trait LlmProvider`, wrong `AnalyticsTracker`/`AnalyticsClient`) and the separate dead **doc-to-doc** link (`AUDIO_MODULARIZATION_PLAN.md`, which never existed in git history). `scripts/check-doc-links.sh` checks path existence only, by design (see design.md D2) — it will not catch symbol-level drift like the two examples above; that class of error is exactly what recommendation B addresses by deleting the hand-written file/symbol listings rather than trying to keep them accurate.
- Depends on changes 01-10 landing first (last in apply order); the exact frontend test script name (change 02) and clippy CI invocation (change 03) must be confirmed against their landed implementation before being written into `docs/CODEBASE_MAP_OPERATIONS.md` (see tasks.md task 4).
