# Proposal

## Why

Every LLM-provider call path builds its own `reqwest::Client` and none of the actual summary-generation calls retry or apply a bounded timeout consistently. `summary/llm_client.rs::generate_summary()` (the single dispatch point used by `summary/processor.rs` for every chunk, combine, and final-report call) has no retry at all, times out after 300s but tells the user "timed out after 60 seconds" (`llm_client.rs:280,301`), and treats a 401 the same as a 503. The five provider modules' model-listing commands each call `reqwest::Client::new()` per invocation (`ollama/ollama.rs:162` `get_models_via_http_async`, `openai/openai.rs:130` `get_openai_models`, `anthropic/anthropic.rs:100` `get_anthropic_models`, `groq/groq.rs:98` `get_groq_models`, `openrouter/openrouter.rs:43` `get_openrouter_models`), so no connection pooling is shared across calls, and only Ollama's model-listing path (`ollama.rs:126-157`, `get_models_via_http_with_retry`) retries — with its own bespoke backoff, not reusable by the other four. A transient network blip or a provider's 503 today either hangs for 5 minutes or fails the whole summary/model-list outright, with no consistent, safe retry policy across providers.

## What Changes

- Add a shared LLM HTTP layer (`frontend/src-tauri/src/llm/`): one process-wide lazily-built `reqwest::Client` (connection pooling, a connect timeout, a request timeout, a fixed user-agent), and a `send_with_retry` helper that retries only on connect errors, request timeouts, HTTP 429, and HTTP 5xx, with bounded attempts and exponential backoff + jitter; it never retries HTTP 4xx auth/validation failures (401/403/400/404) and never retries a request that is already streaming a partial response.
- Add an `LlmError` enum with a `Display`/`to_string()` that reproduces the existing user-facing strings (e.g. `"LLM request timed out after {N} seconds"`, `"LLM API request failed: {body}"`, `"Failed to send request to LLM: {e}"`) so the frontend's error toast (`frontend/src/hooks/meeting-details/useSummaryGeneration.ts:196-198`, which renders `pollingResult.error` verbatim) is unaffected by the refactor; also fix the timeout message to report the real configured timeout instead of the currently hardcoded, incorrect "60 seconds".
- Migrate `summary/llm_client.rs::generate_summary()` and the five provider model-listing functions to use the shared client and `send_with_retry` instead of ad hoc `Client::new()` calls and Ollama's bespoke retry loop; each provider module keeps only its own request-building and response-parsing.
- **BREAKING (behavioral, not API)**: summary generation and model-listing calls now retry transient failures (connect error / 429 / 5xx) up to a bounded number of times with backoff before surfacing an error, where previously they failed immediately; a 401/403 from any provider is now guaranteed to fail without retry (previously ollama's model-list retry loop treated most non-"Invalid endpoint"/"404" errors, including some 5xx-shaped strings, as retryable, and the other four providers had no retry policy of any kind — this makes behavior consistent instead of ad hoc per provider).
- No `trait LlmProvider` is introduced: the five providers' actual request/response shapes differ enough (Claude's `x-api-key`/`ClaudeRequest`/`ClaudeChatResponse` vs. the four OpenAI-compatible providers already unified behind one `match` in `generate_summary`, plus four distinct model-listing response structs) that a shared trait would either be a thin pass-through or force an artificial common shape; only the HTTP mechanics (client, retry, timeout, error mapping) are shared.

## Capabilities

### New Capabilities
- `llm-provider-resilience`: shared, provider-agnostic HTTP behavior for all outbound calls to LLM providers (Ollama, OpenAI, Anthropic/Claude, Groq, OpenRouter, CustomOpenAI) — connection reuse, bounded retry with backoff on transient failures, no retry on authentication/validation failures, and a request timeout — covering both summary-generation calls and provider model-listing calls.

### Modified Capabilities

## Impact

- Code: new `frontend/src-tauri/src/llm/` module (`mod.rs`, `client.rs` for the shared `Client` + `send_with_retry`, `error.rs` for `LlmError`), registered as `pub mod llm;` in `frontend/src-tauri/src/lib.rs`.
- Changed call sites: `frontend/src-tauri/src/summary/llm_client.rs` (`generate_summary`, ~lines 115-330), `frontend/src-tauri/src/summary/service.rs:535` (drop the per-session `reqwest::Client::new()`, use the shared client), `frontend/src-tauri/src/ollama/ollama.rs` (`get_models_via_http_with_retry`/`get_models_via_http_async` at lines 126-200 move to `send_with_retry`; the `Client::new()` sites in `pull_ollama_model` (287) and `delete_ollama_model` (458) switch to the shared client for connection-pool reuse but are **not** wrapped in `send_with_retry` — a 10-minute model download and a delete are not candidates for the same bounded-retry policy as a summary/model-list call, see design.md), `frontend/src-tauri/src/openai/openai.rs:130`, `frontend/src-tauri/src/anthropic/anthropic.rs:100`, `frontend/src-tauri/src/groq/groq.rs:98`, `frontend/src-tauri/src/openrouter/openrouter.rs:43` (also switches from `reqwest::blocking::Client` to the shared async client — see design.md D-OpenRouter-Blocking).
- New dev-dependency: `wiremock` (no HTTP mock crate — `wiremock`/`httpmock`/`mockito` — is currently a dev-dependency of `frontend/src-tauri/Cargo.toml`; `wiremock = "0.5"` is added under `[dev-dependencies]` to test retry/timeout behavior against a real local HTTP server instead of hand-rolled fakes).
- No new runtime dependency: `once_cell` (for the lazy static client) and `rand` (for jitter, already pulled in transitively by existing deps — confirm at implementation time whether a direct `rand` dependency is needed) are the only crates involved beyond `reqwest`, both already available or trivial.
- Out of scope: the diarization/ASR HTTP calls (none exist — those engines are in-process), retrying `pull_ollama_model`'s download or `delete_ollama_model` (they reuse the shared client for pooling but keep their current one-shot error handling — a 10-minute download and a delete are not bounded-retry candidates), streaming responses (none of the five providers currently stream in this codebase — `generate_summary` always awaits a full JSON body), and introducing a `trait LlmProvider` (see What Changes).
