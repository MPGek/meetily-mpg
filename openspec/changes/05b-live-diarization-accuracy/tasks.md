# Tasks

All `uv run --project eval …` commands are run from the repo root (the `--project eval` flag carries the location). `--mode online` is the mode selector introduced by `add-online-diarization-eval` task 4.1; confirm its exact spelling against that change's runner before the first use. Rust verification is `cargo test -p meetily --lib diarization` plus `cargo clippy -p meetily --all-targets --message-format=short` unless a task names something else.

## 0. Baseline

- [ ] 0.1 Record the pre-change baseline for every gated figure: run `uv run --project eval run --dataset voxconverse --run-id base-offline`, `uv run --project eval run --dataset voxconverse --mode online --run-id base-online`, the same pair for `ru-synthetic`, then `uv run --project eval score` for each run id and `uv run --project eval report --run-id base-online`; verify: the report shows offline DER, online DER, the online−offline delta, emission lag median/p90, streaming flip rate, fragmentation, and RTF for both datasets, and those numbers are written into this line as the reference for gates D7 (`voxconverse` DER delta ≤ +3.0, `ru-synthetic` Conf delta ≤ +3.0, `live_final_flip` ≤ 5.0 % on both).

## 2. Deferred re-clustering at stop (design D1)

- [ ] 2.1 Add the `diarizationFinalReclusterEnabled` setting (default on) to the diarization settings surface and thread it into the live session config resolved at session start; verify: `cargo test -p meetily --lib diarization` plus a unit test asserting the session carries the value resolved at start and ignores a later change.
- [ ] 2.2 Implement the stop-time refinement in `streaming/processor.rs`: cluster `mic_emb`/`sys_emb` per channel through the `Clustering` factory from change 05 with the resolved kind, threshold, and effective ceiling, attribute each buffered window to its refined cluster, and assemble the channel timeline with the shared `core/turns.rs` gap-merge; verify: a unit test over a two-voice fixture asserting the refined timeline separates speakers that the incremental ids merged, and that no cluster spans both channels.
- [ ] 2.3 Implement the unconditional fallback: fewer than two buffered embeddings on a channel, a clustering error, or the setting off leaves that channel on the incremental identities and logs the reason; verify: unit tests for all three cases assert the stop completes, returns the incremental labels, and emits the log line.
- [ ] 2.4 Measure the refinement: run `uv run --project eval run --dataset voxconverse --mode online --run-id reclust` and `uv run --project eval score --dataset voxconverse --run-id reclust`, then the same pair for `ru-synthetic`; verify: online DER − offline DER ≤ +3.0 points on `voxconverse` and online Conf − offline Conf ≤ +3.0 points on `ru-synthetic` (gate D7), emission lag median/p90 no worse than the 0.1 baseline, and the added stop-time cost recorded as its own figure in the report.
- [ ] 2.5 Confirm the refinement improves rather than only moves the numbers: compare `reclust` against `base-online` in `uv run --project eval report --run-id reclust`; verify: online DER does not regress on either dataset, and if it does, the setting default flips to off and this task records why before section 3 starts.

## 3. Promotion semantics and correction feedback (design D2, D5)

- [ ] 3.1 Add the provisional/final state to live blocks in `streaming/reconcile.rs` and emit a final revision at stop only for blocks that were undecided or whose refined cluster differs from the displayed one; verify: `cargo test -p meetily --lib diarization` plus unit tests asserting an unchanged block gets no name-changing revision and a changed block gets exactly one final revision.
- [ ] 3.2 Add the `diarizationFinalRelabelAll` opt-in setting that makes the final pass re-emit every block; verify: a unit test asserting the same fixture emits revisions for all blocks with the setting on and only for changed blocks with it off.
- [ ] 3.3 Protect user assignments from promotion: a cluster the user bound and a per-turn override are never revised by the final pass; verify: unit tests asserting the user's identity and `matched_by = "user"` survive a refinement that would assign a different speaker.
- [ ] 3.4 Force a reconcile pass after `PrototypeStore::bind` in the engine's `assign_live_speaker`, so already-emitted blocks of that cluster re-emit a revision with the new display name; verify: a unit test asserting a revision is emitted for a previously emitted block with no further speech arriving, and a Fast-mode recording in which renaming a cluster updates already-visible rows immediately.
- [ ] 3.5 Re-measure after the display changes: `uv run --project eval run --dataset voxconverse --mode online --run-id promote` and `uv run --project eval score --dataset voxconverse --run-id promote`, plus the `ru-synthetic` pair; verify: `live_final_flip` ≤ 5.0 % on both (gate D7) and the streaming flip rate and fragmentation figures unchanged from `reclust` (these tasks change what is re-emitted, not what is clustered).

## 4. `AudioSource` unification (design D4)

- [ ] 4.1 Define `trait AudioSource { fn next_window(&mut self) -> Option<(f64, Cow<'_, [f32]>)>; }` in `core/`, implement `batch::PcmWindows` over the existing `StreamWindows`/ffmpeg stream, and make the batch core consume it; verify: `cargo test -p meetily --lib diarization` with `parity_stream_vs_in_memory_core` passing unchanged, and `uv run --project eval run --dataset voxconverse --run-id audiosrc-offline && uv run --project eval score --dataset voxconverse --run-id audiosrc-offline` reporting the same offline DER as `base-offline` (offline behavior held constant).
- [ ] 4.2 Implement `streaming::VadChunks` over the VAD-filtered chunks the processor receives and feed the same core from it; verify: `cargo test -p meetily --lib diarization` plus an extension of `parity_stream_vs_in_memory_core` asserting the streaming source and the batch source produce the same embedding units for the same audio.
- [ ] 4.3 Measure the boundary-convention risk: `uv run --project eval run --dataset voxconverse --mode online --run-id audiosrc` and `uv run --project eval score --dataset voxconverse --run-id audiosrc`, plus `ru-synthetic`; verify: the D7 gates still hold (`voxconverse` DER delta ≤ +3.0, `ru-synthetic` Conf delta ≤ +3.0, `live_final_flip` ≤ 5.0 % on both); if a gate fails, this step is reverted on its own and the failure recorded here.

## 5. Cache-reusing offline pass (design D3)

- [ ] 5.1 Retain the finished session's per-channel embeddings and refined turns in a single-entry in-memory cache keyed by meeting id inside `engine.rs`, dropped when the next recording starts; verify: `cargo test -p meetily --lib diarization` plus a unit test asserting the cache is replaced on a new session start and never holds two meetings.
- [ ] 5.2 Implement the adequacy test — matching `model_tag`, zero embedding failures for the channel, and `buffered_speech_secs / session_speech_secs ≥ 0.90` from the session telemetry — and log the decision with its inputs; verify: unit tests for each failing condition asserting the full pipeline is chosen and the log names the reason.
- [ ] 5.3 Make offline diarization take the reuse path when the test passes: skip decode, segmentation, and embedding; still run clustering, turn assembly, transcript attribution, and the cluster-cache persistence with the "replace only unassigned rows" rule; verify: `cargo test -p meetily --lib diarization`, plus an app run in which diarizing a just-recorded meeting spawns no ffmpeg process and produces the same speaker labels as a forced full run of the same meeting.
- [ ] 5.4 Confirm the offline path is untouched for meetings without a cache: `uv run --project eval run --dataset voxconverse --run-id cachereuse-offline && uv run --project eval score --dataset voxconverse --run-id cachereuse-offline`; verify: offline DER, FA, Miss, and Conf identical to `base-offline` (the harness never has a session cache, so the reuse branch must be inert there).
- [ ] 5.5 Delete what the unification and the reuse path superseded (any duplicated decode/embedding entry point left after sections 4 and 5); verify: `cargo clippy -p meetily --all-targets --message-format=short` reports no new dead-code warning and `cargo test -p meetily --lib diarization` is unchanged.
- [ ] 5.6 Import and retranscription regression: re-diarize an imported meeting and a retranscribed meeting, neither of which has a session cache; verify: both complete with unchanged speaker labels, and `cargo test -p meetily --lib retranscription` passes.
