### Deviations from design.md
1. `invokeTyped<TResult, TArgs extends object = object>` puts the result type first (callers write `invokeTyped<Foo>('cmd', args)`); D1 wrote `<TArgs, TResult>`.
2. `listenTyped` keeps Tauri's `EventCallback<T>` (handler receives `Event<T>`, read `event.payload`) instead of a payload-only handler, so listener bodies did not change.
3. The lint rule restricts named imports (`invoke` from core; `listen`/`once`/`emit` from event) rather than whole modules, so `convertFileSrc` (`hooks/useAudioPlayer.ts`, not IPC) and the `UnlistenFn` type stay importable; the 6.1 grep therefore lists `useAudioPlayer.ts` for its `convertFileSrc` import only.
- `IpcError.toString()` returns the bare message so `String(err)` / template-literal formatting is unchanged. Visible effect: catches written as `err instanceof Error ? err.message : '<fallback>'` now show the Rust message instead of the fallback (design D1 accepted this). One site needed an edit to keep its output: `useMeetingOperations.ts` `toast.error(error as string || ...)` -> `String(error)`.
- Wrappers keep every arg shape exactly as sent today, including the known-wrong `start_diarization` `max_speakers` key (snake_case, so Rust always gets `None`) - flagged for follow-up, not fixed.
- Known type drift kept on purpose (documented in `models.ts`): Whisper/Parakeet `ModelStatus` stays `{ Downloading: number }` (what the managers build locally) although Rust serializes `{ Downloading: { progress } }`; `components/ModelDownloadProgress.tsx` reads it as a number.
