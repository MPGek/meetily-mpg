# Meetily Codebase Map

> Auto-generated by Cartographer. Last mapped: 2026-08-25
> Project tier: Large (861 files, ~1.93M tokens)

Meetily is a **privacy-first AI meeting assistant** desktop application built with Tauri v2 (Rust + Next.js). It captures, transcribes, and summarizes meetings entirely on local infrastructure — no cloud dependency required. Recent work (since 2026-08-14) focused on **speaker identity registry & voiceprint provenance**, **enhanced-only diarization** (segmentation-3.0 + TitaNet-Large), **incremental audio save durability**, **mic gain / system ducking fixes**, and **clip playback indicators**.

### Core Capabilities
- **Audio Capture**: Microphone + system audio (stereo left=mic/right=sys) with per-channel Silero v6 VAD, RNNoise, HPF, adaptive resampling
- **Diarization**: Enhanced-only Polyvoice (segmentation-3.0 + TitaNet-Large 192-d + AHC MinClusterSize=2), ffmpeg streaming decode, fixed ONNX pool `min(8, 75% cores)`, offline + online (Efficient/Fast) with `PrototypeStore`; **word-level CTC alignment** (`word_alignment/`, wav2vec2 XLS-R 56 + constrained Viterbi) refines per-token timestamps live at block finalization + as offline/stop-time repair, feeding the token N-way split
- **Transcription**: Whisper.cpp (local) / Parakeet ONNX streaming / provider abstraction, provider-aware readiness gate, Enhance re-transcription, import pipeline
- **Speaker Registry**: Global `speakers` + `speaker_embeddings` (voiceprints with provenance, two-owner CHECK, 64-cap), `meeting_speakers` (centroids + exemplars ≤32) + `meeting_expected_speakers` allowlists, cosine matcher τ=0.7, live `assign_live_speaker`/`rematch_meeting_speakers`
- **Summarization**: Multi-provider AI (Ollama, Claude, Groq, OpenAI, OpenRouter + built-in llama-helper) with chunked processing, template system, English-cache, debug logging
- **Storage**: SQLite via sqlx (WAL) + local filesystem audio, meeting folders `YYYY-MM-DD_HH-MM`, checkpoint recovery
- **Playback**: FFmpeg WAV transcode to `44100Hz` temp cache, streaming `AudioPlayer`/`useAudioPlayer`, clip indicator per segment

## Architecture Summary

Meetily is a **desktop application** built with:
- **Tauri 2.x** — Cross-platform desktop wrapper (Rust backend + web frontend)
- **Next.js 14+** — React UI framework (App Router)
- **Rust** — Native audio capture (cpal), Whisper.cpp inference (whisper-rs), Parakeet ONNX (ort), SQLite storage (sqlx), local built-in AI (llama-helper sidecar)

### Key Capabilities

| Capability | Technology | Module |
|------------|------------|--------|
| Audio recording (mic + system) | cpal + per-channel VAD + stereo mixing + RNNoise/HPF + VBR AAC | `audio/` |
| Speaker diarization & recognition | Polyvoice enhanced-only (segmentation-3.0 + TitaNet-Large), streaming ffmpeg decode, AHC | `audio/diarization.rs`, `online_diarization.rs`, `speaker_recognition.rs` |
| Speaker registry & voiceprints | SQLite `speakers`/`speaker_embeddings` + cosine τ=0.7, provenance, review UI | `database/repositories/speaker.rs` |
| Meeting audio playback | FFmpeg WAV transcode + `AudioPlayer` + clip indicator per segment | `audio/audio_file.rs`, `hooks/useAudioPlayer.ts` |
| Live transcription | Whisper.cpp / Parakeet ONNX via provider abstraction | `whisper_engine/`, `parakeet_engine/`, `audio/transcription/` |
| AI summarization | Multi-provider LLM (Ollama/Claude/Groq/OpenAI/OpenRouter + built-in) | `summary/` |
| Meeting storage & recovery | SQLite (sqlx, WAL) + local filesystem + IndexedDB checkpoint | `database/`, `indexedDBService` |
| Desktop notifications | Tauri notification API, consent-gated | `notifications/` |
